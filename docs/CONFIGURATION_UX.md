# Настройки эксперимента: исправление UX

Основание: владелец успешно выполнил отдельную оценку, но не может просмотреть/изменить настройки, понять шаблон промпта, Pipeline и критерии; ошибки запуска находятся вне видимой области.

## Поток

- В «Настройках эксперимента» три самостоятельные формы: «Инструкция модели», «Схема обработки», «Правила оценки». Каждая показывает список сохранённых вариантов, «Открыть / изменить», «Новый». Открытие заполняет форму; сохранение изменения создаёт новый ID, не перезаписывая оригинал. Это явно называется новой копией, не изменением старых запусков.
- Промпт — обычный текст; ответ в JSON описывается внутри инструкции обычными фигурными скобками. Подстановка данных — {{text}}; дополнительно поддерживаются безопасные вложенные поля {{input.text}}/{{customer.name}}, без eval. Неверная переменная сообщает строку/столбец и ожидаемый формат уже при сохранении. Существующие невалидные записи доступны для исправления. При запуске отсутствующее поле объясняется с названием промпта/строкой Dataset и доступными именами полей, без значений данных.
- Pipeline — последовательность обработки: вход → промпт → один вызов модели → ответ. Сейчас поддерживается только такая схема; для создания нужно название, не JSON. Схему JSON-ответа можно описать в промпте, но принудительная JSON Schema-валидация candidate-ответа пока отсутствует. Старую неподдерживаемую схему можно прочитать; замена на поддерживаемую делается явно.
- Правила оценки: таблица key/описание/вес, добавление/удаление строк, видимая сумма весов 1 и порог 0..1. Инструкция судье объясняет подход к оценке; критерии объясняют, что оценивать. Судья всегда возвращает scores/rationale; пользователь не должен писать контракт ответа вручную.
- Ошибки создания — под соответствующей формой, проверки/запуска — непосредственно над кнопками. Разные действия имеют независимые сообщения; polling не стирает ошибку запуска. После изменения полей устаревшая оценка объёма очищается.

## Проверки

Backend: проверка синтаксиса при создании, вложенные переменные/JSON-литералы, отсутствующие поля, неподдерживаемые pipeline при сохранении. Browser: открыть и сохранить копии всех трёх типов, неизменность оригиналов, ошибка в видимой форме запуска, понятные правила судьи. Реальных provider calls в регрессионных тестах нет.

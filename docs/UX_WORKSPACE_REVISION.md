# Перестройка рабочего пространства: запуск и результаты

Дата: 2026-09-23. Статус: UX-предложение по замечаниям владельца, не отчёт о реализации. Основа: INFORMATION_ARCHITECTURE.md и аудит RunsView, RunResults, EvaluationWorkbenchView. Домен Dataset / Pipeline / ModelRoute / Evaluator / RunSnapshot не меняется.

## Диагноз

История уже ограничена высотой 360 px, но отделена от выбранного результата. RunResults выводит полный ответ в ячейке, раскрытие строки добавляет большие тексты, а таблица примеров не ограничена высотой. Перестановка истории и результата не решает проблему. Повтор целиком скрыт, если запуск активен или несовместим; пользователь не узнаёт, где действие и почему оно недоступно. Эксперименты одновременно показывают редакторы, форму запуска, результат и историю — четыре разные задачи.

## Запуски: список рядом с выбранным запуском

Широкий экран: слева компактная история 300–340 px, справа выбранный запуск. В истории короткие строки: тип, дата, статус, прогресс, короткий ID. Полный UUID не является основным заголовком.

```text
История                 Текущий запуск: тип / дата / статус
[поиск] [тип] [статус]   [прогресс] [Отменить] [Экспорт]
короткие строки         [Примеры] [Сводка] [Снимок]
с отдельным скроллом     [поиск] [статус] [модель]
                        [Повторить выбранные N] [С ошибкой N]
                        таблица ограниченной высоты
```

Основная вкладка — «Примеры». Сводка, технический снимок и связанные оценки не отодвигают примеры вниз. При ширине менее 1100 px история становится раскрываемой панелью «Выбрать запуск», закрывающейся после выбора. Не создавать три одновременно прокручиваемые колонки. URL /runs/:id определяет текущий выбор; Back возвращает предыдущий запуск. Polling не сбрасывает фильтры, выделение и скролл.

## Таблица и чтение отдельного примера

- Ответ в ячейке ограничен двумя строками с явным «Открыть». Полный текст остаётся в данных и экспорте. Таблица имеет закреплённую шапку, высоту около 45–55vh и пагинацию; горизонтальный скролл критериев находится внутри таблицы.
- «Открыть» показывает drawer, а не увеличивает высоту строки. На узком экране панель полноэкранная. Закрытие восстанавливает фокус на строке и её позицию.
- В панели: идентификатор/статус/модель, «Предыдущий», «Следующий», «Повторить эту запись»; вкладки «Ответ», «Вход и эталон», «Оценки», «Попытки». Человекочитаемая ошибка видна сразу; технические поля раскрываются отдельно.
- Примеры: поиск по ID и видимому тексту, фильтры статуса/модели, сортировка ID/статуса/времени/числовых критериев. История: поиск ID и доступных имён, фильтры типа/статуса, дата по убыванию по умолчанию.
- Счётчик «Показано N из M», сброс фильтров и «Ничего не найдено». Клиентский поиск допустим только по полностью загруженному набору; иначе серверный. Нельзя выдавать поиск одной страницы за поиск всего запуска.
- Выбор строк сохраняется между страницами по ID. «Все с ошибкой» явно относится ко всему запуску, а не молча зависит от текущего фильтра.

## Отмена и повтор

«Отменить запуск» рядом с прогрессом для queued/running, одинаково для генерации и оценки. Подтверждение: полученные результаты сохранятся, новые запросы остановятся; уже отправленный запрос может не отмениться у провайдера и может быть оплачен. Промежуточное «Отмена запрошена» не выдаётся за мгновенную завершённую отмену.

Построчное «Повторить» доступно в таблице и деталях. Над таблицей всегда есть групповые действия: «Повторить выбранные (N)», «Все с ошибкой (N)», «Все без результата (N)». Недоступные действия отключены с видимой причиной, не исчезают. Подтверждение показывает количество вызовов и сохранение старых попыток в исходном Run. Для оценки отсутствие результата означает отсутствие валидных баллов, не только отсутствие текста.

Повторы используют исходный RunSnapshot. Изменение модели/промпта/критериев создаёт новый запуск. Повтор отменённых записей показывается только после поддержки backend-контрактом.

## Настройка отдельно от запуска

Две адресуемые вкладки «Запуск» и «Настройки», первая по умолчанию. Запуск содержит только выбор данных, инструкции, модели, схемы обработки, проверку/объём/старт. У выбора есть ссылка на нужный редактор. Настройки разделены на «Инструкции», «Схемы обработки», «Правила оценки» вместо трёх одновременно открытых форм. Сохранение новой копии предлагает «Использовать для запуска».

Переключение сохраняет выбор и несохранённый ввод; выход с несохранёнными изменениями требует предупреждения. Новая доменная сущность Experiment ради маршрутизации не нужна. Предпросмотр имеет «Показать / Скрыть инструкцию» без повторного запроса при скрытии; изменение исходной конфигурации инвалидирует его. После старта открывается /runs/:id; полная история не дублируется под настройками.

## Независимые критерии и помощь судье

У независимой оценки отдельная колонка на критерий из snapshot со шкалой в заголовке; общего балла нет. Колонки существуют даже если успешных оценок нет. Ошибка означает «Нет валидной оценки», не ноль. Среднее сопровождается количеством валидных оценок; пропуски не входят в знаменатель.

Разделить «Инструкцию судье» (как анализировать) и «Критерии» (что оценивать, описание уровней, шкала). Подсказка объясняет автоматическое добавление шкал и формата ответа. «Показать запрос судье» открывает собранную инструкцию на одном сохранённом ответе без внешнего вызова. Пользователь не обязан вручную повторять внутреннюю JSON-схему.

## Минимальный первый инкремент

1. Скрываемый предпросмотр, короткие ячейки, ограниченная таблица, drawer деталей.
2. Поиск/фильтры/сортировка истории и примеров; корректный охват набора.
3. Компактная история рядом с результатами на широком экране, раскрываемая на узком.
4. Явный построчный повтор, объяснение недоступности; отмена после готовности безопасного backend-контракта.
5. «Запуск / Настройки» с сохранением ввода и переходом после старта в Run.

Библиотека экспериментов, сравнение нескольких Run и настройка набора колонок — следующие инкременты.

## Приёмка

- На 1440×900 история и шапка запуска видимы одновременно. Длинный ответ не увеличивает страницу. На 1280×720 действия доступны без прокрутки через все примеры.
- На 100 запусках и 500 длинных примерах можно выбрать запуск, прочитать пример и повторить ошибку без перемещения между верхом и низом страницы.
- Поиск/сортировка корректны для всего заявленного набора; polling сохраняет контекст.
- Независимые критерии видны отдельно даже при полностью ошибочном запуске; общего балла нет.
- Для ошибочной записи видно «Повторить» либо объяснение недоступности; подтверждение считает вызовы, старые попытки сохранены.
- Отмена сохраняет результаты, не обещает отмену внешнего списания; повторное нажатие не конфликтует с обработкой.
- Настройка и запуск не развёрнуты одновременно; предпросмотр скрывается; переключение не теряет несохранённый текст.
- Управление доступно клавиатурой; Escape закрывает drawer, фокус возвращается. На 390 px нет горизонтального скролла всей страницы.

Проверять offline Playwright на синтетических длинных текстах, затем расположение на рабочем экране владельца. Внешние модели для проверки компоновки не нужны.

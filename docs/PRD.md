# PRD: LLM Evaluation Workbench MVP

## Продуктовая цель

Сократить время выбора LLM-модели и промпта для конкретной функции продукта. Пользователь должен сравнивать результаты моделей на одном и том же наборе данных, а не вручную проводить несопоставимые запросы.

## Пользователь

Первый релиз рассчитан на одного владельца проекта. Позднее появятся роли администратора, исследователя и наблюдателя.

## Основные сценарии

1. Добавить провайдера, сохранить ключ и проверить подключение.
2. Загрузить или создать датасет в CSV/JSONL, проверить его и увидеть предварительный просмотр.
3. Создать версию промпта с переменными входных данных.
4. Создать эксперимент: выбрать датасет, candidate-маршруты, промпт, параметры и Judge.
5. Запустить эксперимент, наблюдать прогресс и ошибки по строкам.
6. Сравнить агрегированные и построчные результаты, скачать CSV/JSON.

## Границы MVP

В MVP входят защищённые секреты, text+vision inputs, локальные изображения, CSV/JSONL import, промпты, запуск нескольких явных маршрутов, отдельная LLM-Judge-конфигурация, история и экспорт.

Не входят: многопользовательский режим, серверное развертывание, PDF, плагины, автоматическое формирование или разметка датасета, неограниченная поддержка провайдеров.

## Контракт датасета v1

Каждая запись обязана иметь `id`. Резервные поля: `input_text`, `images`, `expected_output`, `metadata`. CSV хранит `images` и `metadata` JSON-строкой; JSONL использует массив и объект. Незаполненный `expected_output` разрешён.

Для food-vision изображение должно быть локальным asset, связанным с записью. В первой версии внешние URL не импортируются автоматически.

## Food Vision Judge v1

Judge возвращает JSON без Markdown. Каждый критерий — целое 1–5.

| Критерий | Вес |
| --- | ---: |
| food_type_accuracy — корректность блюда/основных продуктов | 0.35 |
| ingredient_precision — нет выдуманных ингредиентов | 0.25 |
| ingredient_completeness — учтены видимые компоненты | 0.20 |
| uncertainty_and_evidence — честно указана неопределённость | 0.10 |
| instruction_following — соблюдены запрос, язык и формат | 0.10 |

`weighted_score = 0.35*A + 0.25*P + 0.20*C + 0.10*U + 0.10*I`.
Результат `passed`, если score не ниже 3.5 и первые два критерия не равны 1. Judge не должен требовать невидимые ингредиенты и не должен угадывать их.

## Критерии готовности MVP

Пользователь импортирует датасет с фотографиями, выбирает минимум два vision-маршрута и отдельного Judge, получает ответы, попытки, ошибки, latency, usage и Judge-вердикт для каждой строки. Данные сохраняются после перезапуска. API и интерфейс никогда не показывают API-ключи.

## Подтверждённые решения владельца

Данные, включённые владельцем в Dataset, могут передаваться выбранным providers через явные Pipeline bindings. Judge обязан вернуть JSON, а criteria, weights и quality threshold настраиваются в EvaluationSuite. Default matrix: до 100 rows × 3 prompts × 5 routes, concurrency 3, timeout 60 seconds; route/provider может требовать больший timeout. Первый экран сравнивает models при одном prompt; победитель проходит quality threshold, затем сравнивается по latency, cost и error rate.

# Проверка отдельной оценки

1. Возьмите один текст и одну модель. Получите ответы через Главную или Эксперименты. Шаблон выбранного промпта теперь применяется, например: «Кратко перескажи: {{text}}».
2. В завершённом запуске нажмите «Оценить ответы».
3. Выберите модель-судью и сохранённые правила. Правила создаются в Экспериментах, в том числе кнопкой рекомендуемой настройки. В таблице критериев заполните ключ, описание и вес; сумма весов 1, порог 0..1. Описание объясняет судье, что именно оценивать.
4. Проверьте инструкцию судье: {{input}}, {{reference}}, {{output}} — исходные данные, эталон и уже полученный ответ. {{output}} обязателен. Эти данные передаются выбранному провайдеру при явном запуске оценки.
5. Проверьте количество вызовов перед кнопкой. Для одного ответа это один Judge-вызов; candidate-модели повторно не вызываются.
6. Нажмите «Запустить отдельную оценку». Откроется новый Run. Разверните строку: видны оцениваемый ответ, JSON-баллы и обоснование. Ошибка JSON/шкалы не превращается в нулевой score.
7. «Открыть исходные ответы» возвращает к источнику. «Предыдущие оценки» хранит историю. Можно выбрать другую модель или инструкцию и оценить повторно.

Offline-судья выдаёт только тестовые баллы, не качество. Для реального smoke выберите своё подключение с бесплатной моделью и доступным ключом. Квоты и доступность определяет провайдер. Агент реальные вызовы в этом инкременте не выполнял.

Старые технические оценки сохранены и помечены предупреждением; их ответы можно оценить новым отдельным судьёй.

## Как открыть и изменить настройки

### Независимые шкалы и повтор отдельных записей

В новых правилах выбран режим «Независимые оценки по своим шкалам». Задайте каждому критерию минимум и максимум (например, 0 и 5), опишите смысл баллов. Веса и общий порог не нужны. В результате появятся отдельные столбцы критериев и средние по каждому из них. Старые правила открываются в прежнем взвешенном режиме; переключение и сохранение создают новую копию.

В завершённом запуске отметьте строки и нажмите «Повторить выбранные», либо выберите все с ошибкой / без результата. Перед подтверждением виден объём вызовов. Повтор остаётся в том же запуске и использует исходные настройки. Последний ответ отображается в строке, предыдущие доступны через «Попытки». Уже выполненные оценки судьи не обновляются автоматически: они сохраняют оценивавшийся ответ.

Во время обработки повтор заблокирован. После завершения отмены можно повторить выбранные отменённые строки; старые запуски без полного snapshot не поддерживаются. В каждой строке есть действие «Повторить», а полное содержимое открывается кнопкой «Открыть». Пустой или усечённый ответ новой генерации считается ошибкой; для старых completed без ответа выводится предупреждение.

При CSV-сопоставлении текстового эталона выберите «Обычный текст → reference.text». JSON нужен только для структурированного эталона. Сравните первые исходные строки и блок «После преобразования».

На странице «Эксперименты» откройте «Настройки эксперимента». Выбор сохранённой инструкции, схемы обработки или правил оценки заполняет соответствующую форму. Измените поля и нажмите «Сохранить новую копию»: оригинал и предыдущие результаты сохранятся.

Инструкция модели — обычный текст. Для вставки текста строки используйте {{text}} или {{input.text}}; для вложенного поля — {{customer.name}}. Пример JSON-ответа пишите обычными скобками: {"summary": "краткий итог"}. Двойные скобки нужны только для подстановок, не для всего JSON. Выражения и функции не поддерживаются.

Pipeline («Схема обработки») — порядок действий, а не формат ответа. Сейчас это один вызов модели; достаточно названия. Требуемый формат ответа опишите в инструкции. Принудительная проверка ответа по JSON Schema пока не реализована.

В «Подробной проверке и запуске» выберите датасет и инструкцию, затем «Показать инструкцию для первой строки». Проверьте подставленные данные до вызова модели. Предпросмотр бесплатный и локальный; он не проверяет все строки. Ошибки проверки и запуска теперь показаны рядом с кнопками.

В форме судьи можно выбрать сохранённую инструкцию с {{output}}. Критерии определяют, что оценивать, инструкция — как оценивать. Служебную схему scores/rationale приложение добавляет автоматически; отдельный Pipeline для судьи не нужен.

Для каждого критерия опишите смысл крайних и промежуточных баллов, например: «0 — ключевые факты потеряны; 3 — отражены основные факты, есть пропуски; 5 — все существенные факты сохранены». Числовые границы берутся из полей шкалы и добавляются автоматически. Не требуйте в инструкции другой формат ответа вместо scores/rationale. Сейчас служебные требования добавляются к тексту инструкции, отдельного system-role сообщения нет.

Ошибка ответа судьи означает отсутствие оценки, а не ноль. Независимые критерии отображаются отдельными столбцами без общего балла; средние учитывают только успешные оценки. При truncated_response увеличьте лимит выходных токенов или сократите ожидаемый ответ. Для ЦРТ МКО поддержка этого лимита не гарантируется.

Кнопка отмены останавливает последующие строки; уже отправленный запрос может завершиться и быть оплачен. До фактической остановки показывается cancelling. Настройка и запуск эксперимента разделены режимами «Настройки» и «Запуск»; после старта открывается страница результатов.

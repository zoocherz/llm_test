Идея:
Реализовать сервис для тестирования различных функций, решаемых с помощью LLM моделей.
В рамках разработки продуктов некоторые функции выполняют AI-агенты с использованием LLM. В процессе разработки надо выбрать наиболее подходящую модель LLM (как правило выбирается из соотношения качества/скорость/стоимость/размер) и наиболее подходящий промт.
Примеры функций:
* Аннотация телефонного разговора
* Тематизация текста
* Классификация текста
* Поиск именных сущностей в тексте
* Определения состава блюда по фотографии
* Считывания показания весов по фотографии

Для тестирования отдельной функции, как правило, используется отдельный датасет. Каждая функция проверяется по отдельному набору параметров (важному именно для этой функции), но всегда учитывается скорость ответа модели. Один из способов оценки ответа - метод Судьи, когда результат оценивает другая более старшая (более умная модель).
В рамках тестов может быть один промт, и несколько моделей, одна модель и несколько промтов.
Доступ к моделям для тестирования осуществляется через API. Система должна поддерживать набор стандартных провайдеров и их моделей для тестирования, такие как OpenAI, Claude, Google, OpenRouter, Z.ai, Grog, GigaChat, YandexAi и другие. Так же система должна поддерживать кастомные площадки (в том числе платформу собственной разработки), как для доступа к моделям тестирования, так и для доступа к моделям судьям.

Доступ к платформе должен быть через WEB.
В настройках должна быть возможность добавить провайдеров, указать API key и другие настройки.
Должна быть возможность создать тест. В рамках тестов должна быть гибкая настройка что тестируем (модель, промт), на чём тестируем (датасет), с помощью чего тестируем (метрики, судья).
Должна быть возможность запустить тест, просмотреть результат и сохранить его в виде отдельного файла.
При этом создание и настройка тестов и их запуск не должны быть сложными, замудрёнными. Система должна быть как можно проще. Чтобы можно было её быстро освоить и легко пользоваться.

В первое время система будет запускаться локально на Windows машине. Позже предполагается перезд в сеть на арендованный сервер. Следовательно должна быть авторизаци и другие защиты.

Система должна вести историю запусков, и логирование действий пользователей.

Система должна учитывать, что при работе с проваёдерами могут быть ошибки доступа, кончаться лимиты или другие проблемы. Система должна корректно обрабатывать все события и принимать правильные действия. В каких-то случаях выполнять повторный запрос, в каких-то пытаться починить систему.
Дополнительно должен быть режим работы в пуле, когда при отсутствии доступа к одному из провайдеров система переходит к следующему доступному.

В интерфейсы должны быть доступны функции проверки доступа, как к провайдеру, так и к отдельным моделям.

В системе должен быть список моделей, которые предоставляет провайдер, чтобы не вбивать их в ручную. Должна быть возможность обновить актуальный список для отдельного или всех провайдеров.
